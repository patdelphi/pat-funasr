﻿﻿﻿﻿# Pat WebUI 手工冒烟清单

说明：用于本地 MVP 主流程的人工验证，目标是快速确认功能可用、错误可见、不会卡死。

## 前置条件

- 已能运行后端 API（`/v1/models`、`/v1/audio/transcriptions` 可用）
- 已能运行 Pat WebUI：运行 "run_ui_pat.bat"
- 准备 1 个小音频文件（推荐 5~15 秒，wav/mp3/mp4 均可）

## 1. 启动与页面加载

- [ ] 运行 "run_ui_pat.bat"
- [ ] 浏览器打开 `http://127.0.0.1:7861/`
- [ ] 页面不白屏，主要区域可见：模型、输出格式、音频上传、开始识别、下载结果、批量区

## 2. 模型列表

- [ ] 启动后模型下拉框有数据（来自 `GET /v1/models`）
- [ ] 点击“刷新模型列表”，列表能刷新
- [ ] 模型摘要区可见，且能看到 `已加载 / 按需加载` 两类状态文案

## 3. 单文件转写（主链路）

- [ ] 选择模型（默认可用）
- [ ] 上传 1 个音频/视频文件
- [ ] 输出格式选择 `txt`
- [ ] 点击“开始识别”
- [ ] 识别结果区出现文本
- [ ] 下载结果区生成可下载文件

## 4. 多格式输出与一致性

- [ ] 分别选择 `srt` / `vtt` / `tsv` / `json` / `verbose_json` / `all`
- [ ] 每次点击“开始识别”后，预览内容与下载文件内容一致
- [ ] `all` 下载为 zip，zip 内文件齐全且扩展名正确

## 5. 高级参数（透传与白名单）

- [ ] 展开“高级参数”Accordion
- [ ] 修改 `language` / `hotword` / `vad_preset` / `merge_vad` / `use_itn` 等参数后再次转写
- [ ] 后端无 400（字段不被拒绝），且参数改变不导致页面异常

## 6. 批量与队列

- [ ] 批量上传 2 个文件
- [ ] 点击“批量执行”
- [ ] 批量结果区实时显示进度（总进度 + 单文件状态）
- [ ] 批量下载结果生成 zip

## 7. 错误展示（必须可见）

- [ ] 后端不可用：将 base_url 改为无效地址后点击“开始识别”，页面应显示错误信息且状态可恢复
- [ ] 不支持格式：选择非法 response_format（如通过脚本/改代码触发）应显示 400 错误信息
- [ ] 空文件：上传 0 字节文件应显示错误信息（不崩溃、不卡死）

## 8. 流式识别与 Mic

- [ ] 打开“流式识别”页，页面保持左右两栏：左侧“文件流式识别”，右侧“Mic 实时识别”
- [ ] Mic 区首次渲染即显示 Gradio 原生录制控件，不出现额外的“加载流式模型”按钮、自定义设备下拉或 `/mic-stream` 跳转入口
- [ ] 点击“录制”后，状态框显示模型 ready / 加载失败等明确状态
- [ ] 正常录音时，“麦克风信号”显示采样率、样本数、峰值、RMS 等信息
- [ ] 正常识别时，“Mic 流式输出”出现连续文本，短句不被自动拆成多行
- [ ] 停止录音后再次点击“录制”，能够创建新会话并继续识别
- [ ] 点击“生成 Mic 结果下载”，下载结果生成 `.txt` 文件，内容与 Mic 输出一致
- [ ] 文件流式识别与 Mic 实时识别互不覆盖状态、输出和下载文件
